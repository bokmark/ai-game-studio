# 原型代码标准(放宽)

原型是用于验证想法的一次性代码。标准有意放宽,以最大化迭代速度。目标是学习,而非生产质量。

## 原型中允许的做法
- 硬编码数值(无需数据驱动配置)
- 极少或无文档注释
- 简单架构(不要求依赖注入)
- 单例和全局状态
- 复制粘贴的代码(无需抽象)
- 保留调试输出
- 占位美术和音频
- 快速而粗糙的解决方案

## 仍然必须遵守的要求
- 每个原型位于自己的子目录:`prototypes/[name]/`
- 每个原型必须有 `README.md`,包含:
  - 正在验证的假设
  - 如何运行原型
  - 当前状态(in-progress / concluded)
  - 结论(原型结束时更新)
- 生产代码不得引用或导入 `prototypes/` 中的内容
- 原型不得修改 `prototypes/` 之外的文件
- 原型不得部署或发布

## 原型成功后
如果原型验证了某个概念且该功能进入生产:
1. 原型代码不直接迁移——按生产标准重写
2. 原型 `README.md` 中的结论为生产设计文档提供依据
3. 原型目录保留作参考,但不再扩展

## 清理
已结束的原型应在记录结论后归档或删除。
绝不要让原型代码通过渐进式「清理」演变成生产代码。
