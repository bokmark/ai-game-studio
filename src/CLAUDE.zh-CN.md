# 源代码目录

在本目录编写或编辑游戏代码时,遵循以下标准。

## 引擎版本警告

LLM 的训练数据早于锁定的引擎版本。
**使用任何引擎 API 前,务必查阅 `docs/engine-reference/`。**
不要猜测知识截止后的 API 签名——先查文档。

## 编码标准

- 所有公共 API 必须有文档注释
- 玩法数值必须**数据驱动**(外部配置文件),绝不硬编码
- 为可测试性,优先使用依赖注入而非单例
- 每个新系统需要在 `docs/architecture/` 中有对应的架构决策记录(ADR)
- 提交必须引用相关的故事 ID 或设计文档

## 文件路由

根据所编写文件的类型匹配相应的引擎专家代理。
参见 `CLAUDE.md` → Technical Preferences → Engine Specialists → File Extension Routing。

如有疑问,使用 `CLAUDE.md` 中配置的主引擎专家。

## 测试

测试位于 `tests/`,不在 `src/`。
如果测试框架尚不存在,运行 `/test-setup` 进行脚手架搭建。
每个玩法系统都应有覆盖其公式和边界情况的单元测试。

## 验证驱动开发

添加玩法系统时先写测试。
UI 变更通过截图验证。
标记工作完成前,将预期输出与实际输出对比。
